# Website Agent Worker

Production-oriented website checking service for the per-store agent dashboard.

See `APP-INTEGRATION.md` for the exact main-app boundary and `DEPLOYMENT.md` for
the production release and incident runbook.

## What is the "brain"?

The model is the reasoning engine. Durable memory belongs to the company and is
stored in the database:

- every run and per-rule result is immutable audit history;
- findings generated by the model are explicitly unverified;
- lessons become trusted only after a human confirms or corrects them;
- verified lessons are retrieved before later checks;
- rubric versions prevent scores from being compared against changed rules;
- screenshots and page evidence explain why a score was assigned.

The service never trains on its own answers automatically. This avoids feedback
loops where one incorrect answer becomes a permanent company rule.

## Runtime layout

One codebase supports two processes:

1. `npm start` runs the authenticated HTTP API.
2. `npm run worker` claims durable jobs and performs browser/AI work.

They may run together on one computer for development. The API can remain on a
small hosted service while the browser worker runs on an always-on Mac. A
database lease prevents two workers from completing the same job.

## $0 API-cost Mac worker

The worker supports two reasoning providers:

- `AI_PROVIDER=openai` uses the OpenAI API and requires `OPENAI_API_KEY`.
- `AI_PROVIDER=codex` runs the local signed-in Codex CLI. The macOS installer
  pins `gpt-5.6-sol`, uses ephemeral read-only executions, and never asks for an
  OpenAI API key.

The Codex route uses the ChatGPT/Codex plan allowance of the user signed in on
that Mac. It does not create per-token API charges, but it is not unlimited and
may pause when plan limits are reached. Start with a measured pilot before
increasing daily volume.

On the always-on Mac, clone this public repository, check out the production
branch, then run from `agent-worker`:

```bash
npm run install:macos
```

The installer verifies Node.js 24+, the signed-in Codex app, and PostgreSQL TLS;
installs Chromium; applies migrations; creates a restricted database role;
stores its generated password in macOS Keychain; and registers a LaunchAgent
that restarts after failures and user login. The Supabase owner password is read
once with hidden input and is never written to disk.

## Data stores

- SQLite is supported for local development and single-machine evaluation.
- PostgreSQL is required for production durability, concurrent workers, backups,
  and vector retrieval. Apply `migrations/001_initial.sql` before starting.
- Browser evidence is represented by hashes and metadata. A production object
  storage adapter must be configured before retaining screenshot files.

## Security defaults

- The API refuses unauthenticated requests. Production mode verifies short-lived
  OIDC/JWT access tokens against an allowlisted issuer, audience, algorithm, and
  JWKS endpoint. Static bearer tokens are a development bridge and production
  rejects them unless the operator explicitly accepts that risk.
- OpenAI keys, when the API provider is selected, are read only from server
  environment variables. The Codex provider requires no OpenAI API key.
- Website URLs are resolved and rejected when they target private, loopback,
  link-local, or otherwise unsafe addresses.
- Browser network hosts and retained screenshot bytes are capped. Production
  must also deny private and cloud-metadata networks at the infrastructure egress
  layer, which closes DNS time-of-check gaps outside the application process.
- The browser is isolated, uses a fresh context, blocks downloads, and performs
  read-only inspection. It does not submit forms or complete purchases.
- Website content is treated as untrusted input, never as agent instructions.
- CORS is allowlisted; no `*` production origin is accepted.

The existing app currently has no production identity token. Connect its sign-in
provider to `window.AGENT_EXECUTOR_CONFIG.getAccessToken`; that callback must
return a fresh access token. The browser never receives the OpenAI key or the
database password.

## Local setup

```bash
cp .env.example .env
npm install
npx playwright install chromium
npm test
npm start
```

Run the worker in another terminal:

```bash
npm run worker
```

Do not commit `.env`, API keys, database passwords, or browser session data.

## API summary

- `POST /v1/checks` queues an idempotent check.
- `GET /v1/checks/:jobId` returns status and completed results.
- `POST /v1/checks/:jobId/feedback` confirms or corrects one finding.
- `POST /v1/lessons` teaches an explicit company lesson.
- `GET /v1/lessons?storeId=...` lists company and store memory.
- `DELETE /v1/lessons/:lessonId` revokes an incorrect lesson without erasing its audit trail.
- `GET /health/live` is process liveness.
- `GET /health/ready` checks database readiness.

Every mutating request accepts `Idempotency-Key`. Authentication determines the
organization; callers cannot select another organization in the JSON payload.
